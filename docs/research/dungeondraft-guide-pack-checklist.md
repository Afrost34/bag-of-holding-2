# Mapping Dungeondraft's whole guide onto Forgotten Adventures packs

Dungeondraft (DD) can be cloned with Forgotten Adventures (FA) art alone, but only if the pack sorter is fixed first and four things are synthesised in code from textures rather than found as art: ground roads, roof geometry, cave brush art and tile sets. The pack sorter currently files none of the 169,988 unique FA pictures as "Not sorted" but misfiles roughly 3,000 of them, including **664 wall strips filed as wall pieces** because the wall-strip rule matches only `Straight_Path` and misses names ending `_Path` ([FA listing analysis, section 3 of the pack notes]). The build order below puts that fix first, then the shared pointer grammar (click, finish, Backspace, Shift-bend, Alt-erase, Edit Points), then FA-driven walls, portals, floors and terrain, then lighting, select/prefab tooling and export. Core corrections to carry into code: FA lit lamps are `_Lit` (440 files), not `_Glowing`; wood wall strips are `Shack_Wall_Wood_*_Path`, not `Straight_Path`; FA art is 200 px per square, not DD's 256; and `.dd2vtt` is a JSON file in squares with `format`, `resolution`, `line_of_sight`, `objects_line_of_sight`, `portals`, `environment`, `lights` and `image` ([Arkenforge UVTT spec](https://arkenforge.com/universal-vtt-files/)). The guide is written for DD 1.2.0.1 ([guide](https://dungeondraft-encyclopaedia.gitbook.io/guide/introduction/dungeondraft-encyclopaedia.md)). Priorities: M = must, S = should, C = could. Pixel sizes (800x200 wall strip, 600-1200 px textures, 200 px/square) come from the owner's brief and file names, not measured images, so one index script must measure them.

## Dungeondraft asset types map onto FA folders through suffixes, not folder names alone

FA has no ready-made tile sets, no ground-road strips, no roof pieces and no cave brush art; everything else maps cleanly. The decisive signals are the extension (a `.jpg` is an opaque seamless tile; every `jpg` in the Core zip sits inside a `Textures/` folder), a trailing `_Path` (a strip to draw along a line) and a trailing `_WxH` (footprint in squares) ([pack notes, section 2](https://dungeondraft-encyclopaedia.gitbook.io/guide/custom-assets-and-mods/importing-assets/packing-your-assets.md)). DD authors everything at 256 px per square, objects as PNG, terrain as seamless PNG with alpha as height, walls as black-and-white strips plus `_end`, portals exactly 256 px wide, and roof and cave packs have no published rules ([DD Custom Assets Guide](https://raw.githubusercontent.com/wiki/Megasploot/Dungeondraft/Custom-Assets-Guide.md)).

The DD "Colorable" mechanism (reddish pixels recoloured) has no FA equivalent because FA pictures are fully coloured and carry the colour in the file name (stone Earthy/Redrock/Sandstone/Slate/Volcanic, wood Ashen/Dark/Light/Red/Walnut, metal Gray/Rusty/Black/Brass...). The rule is: group sibling files that differ only by one colour token into one picker entry with swatches, and give every other item a multiply tint plus alpha; wood-and-stone walls such as `Wall_BrickWood_Earthy_Ashen_A` carry two tokens and group by the pair.

Lit lamps use the suffix `_Lit`: the pairs are `X.webp` plus `X_Lit.webp`, and only a handful of Ceremorph expansion files contain "Glowing" (`Ceremorph_Blue_Glowing_Orb_Holder_A1_1x1.webp`). The `litVariant(path)` helper should swap `_Lit` and `_Unlit`/plain, and the default-light table in `packDefaults.ts` should key on Lightsources folder plus `_Lit`, never on "Glowing".

Import only what adds files. Core 1.04 (148,689 images) and Expansion 1.14 (19,272 images) share zero stems, the legacy PNG expansion zips are fully covered, all 13 " (n)" zips have byte-identical listings to their originals, and 37 of the 44 monthly `Assets_LU_*` zips are subsets of Core/Expansion. Seven deltas still carry new stems (`Assets_LU_26_February_03` 440, `26_March_02` 384, `26_March_01` 145, `25_September_04` 66, `26_July_01` 3, `25_August_03` 2, `25_September_01` 1). Skip `Assets_CU_25_August_01` (all in Core) and the two `Prefabs_*` zips (about 46 new names, all in Prefabs_10; stem-level dedupe misses them because Core reorganised folders, so dedupe by base name). Dedupe on stem without extension, prefer webp over png, never convert jpg; matching textures by name across extensions otherwise fails, as DD's own search mod warns ([Additional Search Options](https://dungeondraft-encyclopaedia.gitbook.io/guide/custom-assets-and-mods/some-useful-mods/additional-search-options.md)). Content updates inside a same-stem file are invisible from name lists.

## Export and the `.dd2vtt` field list

DD offers PNG, JPEG, WebP and Universal VTT, a default 256 PPI capped at 300, quality 75-90% recommended, a 16384 px VTT limit, Crop, Grid and Lighting toggles, camera filter, source and overlay level ([Quality settings](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/quality-settings.md), [Visual settings](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/visual-settings.md)). The gitbook UVTT page lists only contents (image, walls, portals, caves, lights, grid PPI) and gives no JSON ([UVTT page](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/universal-vtt.md)); the field list comes from Arkenforge. FA's lossless export PPI is 200, not 256; a 100x100-square map at 200 PPI is 20,000 px and must be capped or downscaled, and render must tile when it exceeds `gl.MAX_TEXTURE_SIZE`.

| `.dd2vtt` field              | Type and unit                                                                                                                    | BoH source                                                 |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `format`                     | decimal version (0.3 in practice; assumption, verify)                                                                            | constant                                                   |
| `resolution.map_origin`      | `{x, y}` squares, usually 0                                                                                                      | crop origin                                                |
| `resolution.map_size`        | `{x, y}` in squares                                                                                                              | width/height px / ppi                                      |
| `resolution.pixels_per_grid` | int                                                                                                                              | export PPI                                                 |
| `line_of_sight`              | array of polylines `[{x,y}...]` in squares (walls; closed shapes repeat the first point); "caves" are just closed polylines here | wall paths flattened by `splinePoints`, room/cave outlines |
| `objects_line_of_sight`      | same shape                                                                                                                       | traced alpha outlines of `blockLight` stamps/paths         |
| `portals[]`                  | `position`, `bounds` (two end points), `rotation` (radians), `closed`, `freestanding`                                            | portal items; set `closed` for doors, false for windows    |
| `environment`                | `baked_lighting` bool, `ambient_light` hex                                                                                       | export lighting flag, ambient                              |
| `lights[]`                   | `position`, `range` (assumed radius in squares), `intensity`, `color`, `shadows`                                                 | light items                                                |
| `image`                      | base64 PNG or WebP                                                                                                               | exported composite                                         |

Coordinates are in squares, y down, origin top-left ([Arkenforge](https://arkenforge.com/universal-vtt-files/)). Colour string length (8 hex digits seen in files) and the `range` convention are unconfirmed, so a unit test should pin them after importing a sample into Foundry or Owlbear.

## Remaining gaps and what to check before coding

Evidence is strong on controls and weak on internals. Unresolved: the numeric layer IDs for portals, roofs and Above Roofs, and the full tool-layer names (screenshot only); the labels of the three "disable" checkboxes and the Map Wizard's lists; the wall corner naming (which of `Corner_A..H`, `Corner_In/Out`, `Connector_*`, `Joint_*` is the L, T or X piece, needing a visual check of one set); wall thickness and the 800x200 strip size; which roof `.webp`/`Grates` have alpha; door orientation (Core 1x1 doors have no open/closed token, only Cellar/Vault do); Arctic and Desert water/snow folders; the `.dd2vtt` `format`, colour length and `range` units; DD's intensity-to-weight curve, shore falloff and fade length; and the second video (Moulk, 2024) which yielded no transcript. Two earlier-report points differ from the folder notes: the folder notes win, so wood strips are `_Path` strips and lit lamps are `_Lit`. FA licence terms for runtime tinting and for re-exporting FA art are unchecked and need the owner.

## Conclusion

The checklist reduces to a repeatable pattern: every DD tool is a generator over pieces the FA packs already contain, with colour carried by file name and tint, and the work that remains is indexing correctly and sharing one input grammar. The surprising result is that fixing the sorter is the largest single-feature win, since it lifts wall strips from 295 to 954 and unlocks wood, dwarven, drow, desert and flesh walls at once. Dungeondraft's own limits (portals deleted on edit, sorting locked after drawing, no pattern holes, no wall thickness, one-line text, no align) should be treated as a to-beat list rather than a spec, so the four deliberately synthesised pieces (roads, roofs, caves, lighting falloff) are where new design effort belongs.
