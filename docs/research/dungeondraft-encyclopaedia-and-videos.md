# Dungeondraft tool by tool: a cloneable behaviour spec

Dungeondraft is a size-only, always-all-tools editor, so the owner's type-less creator design copies its real structure. Every tool is a mode with one consistent input grammar: click adds a point, Right-click, double-click or Enter finishes, Delete or Backspace removes the last point, Shift after the first point bends a curve, Alt erases, and Ctrl/Cmd continues or merges. Shapes stay editable through an Edit Points mode ([shortcuts](https://dungeondraft-encyclopaedia.gitbook.io/guide/general-info/mouse-and-keyboard-shortcuts.md), [Wall tool](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/wall-tool.md)). Ordering is a small fixed stack of numbered layers (user layers 100 to 400) with an Over/Under flag inside each layer. Levels are separate stacked maps, not layers, and a Compare Levels overlay lines them up. The grid (G) and snap (S) are independent toggles. Maps are 1 to 200 squares on a side at 256 px = 5 ft per square. Packs are zip-like archives of 256 px-per-square PNGs sorted into category folders. Export is PNG, JPEG, WEBP or Universal VTT (.dd2vtt), with a 300 PPI cap and a 16384 px VTT limit ([export](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/quality-settings.md)). This report merges the Dungeondraft Encyclopaedia (written for version 1.2.0.1), the developer's asset guide, the old 0.9.2.0 Unofficial Manual and one 2020 alpha video walkthrough. It extends the earlier Dungeondraft report, whose still-valid findings are folded in. It ends with a build mapping and an honest gap list: the 2024 beginner video had no obtainable transcript, the gitbook "unofficial-dd-manual" was not read, and current numeric layer IDs for roofs, portals and Above Roofs are unconfirmed.

Source note: "Gitbook" below means the Encyclopaedia at dungeondraft-encyclopaedia.gitbook.io/guide, fetched as raw pages. "Manual 0.9.2" is the old Unofficial Manual PDF ([docdroid](https://www.docdroid.net/file/download/mDwhitS/dungeondraft-v0920-toxic-pangolin-the-unofficial-manual-pdf.pdf)), used mainly for layer numbers and is out of date where it conflicts. Ctrl means Ctrl on Windows/Linux and Cmd on Mac.

## The input grammar that every tool shares

Reading the tool pages side by side shows one grammar reused almost everywhere. Learn it once and you have specified most of the creator's pointer logic.

**Point tools (Wall, Path, Pattern Shape freeform, Building freeform, Roof Manual).** A click places a point. The gitbook says Wall and Path finish with **Right-click, double-click or Enter**, and ending on the start point closes the shape automatically. **Delete or Backspace** removes the last placed point while drawing. **Shift held after the first point** turns the next segment into a curve ([shortcuts](https://dungeondraft-encyclopaedia.gitbook.io/guide/general-info/mouse-and-keyboard-shortcuts.md)). The 2020 video shows the curve gesture concretely: click the start, then hold Shift while pressing and dragging the mouse, which creates a spline controlled by the start and end anchors. You release Shift and the button, keep adjusting freely, and a further click resumes normal wall drawing ([video 9:52-10:42](https://www.youtube.com/watch?v=LKbwhrC4vRA)). When the cursor reaches the starting point it turns green, which means the wall is closed. A plain double-click there yields a semicircle, and a full circle needs Shift+drag again ([video 10:42-11:15](https://www.youtube.com/watch?v=LKbwhrC4vRA)). The gitbook tip for a full circle is Snap to Grid plus four quarter-circle curves ([Wall tool](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/wall-tool.md)). Enter, Esc, Right-click and double-click for Building, Pattern Shape and Roof are **not documented** on those pages. The gitbook only says Esc is a general "back out" ([shortcuts](https://dungeondraft-encyclopaedia.gitbook.io/guide/general-info/mouse-and-keyboard-shortcuts.md)).

**Edit Points mode (Wall, Path, Pattern Shape, Building).** A button in the tool panel enters the mode. Dragging a point moves it, clicking on the outline adds a point, hovering a point and pressing Delete/Backspace removes it, and hovering between two points on a Wall and pressing Delete deletes that segment and splits the wall. Clicking one of the shape buttons exits the mode ([Wall](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/wall-tool.md), [Building](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/building-tool.md), [Pattern](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/pattern-shape-tool.md), [Path](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/terrain-tab/path-tool.md)). Editing wall points removes any portals on that wall.

**Brush tools (Cave, Water, Material, Terrain).** Brush size comes from the mouse wheel or `[` and `]`, or size icons. Holding **Alt while painting erases** in the Building, Cave, Water and Material tools. In the video, Alt also changes the cursor colour to show subtract mode, and Alt can add sections back as well as remove them ([video 9:22-9:37](https://www.youtube.com/watch?v=LKbwhrC4vRA)). Terrain has no erase: a texture is removed by painting another over it.

**Snapping.** S toggles snap (it also shows in the bottom bar), and G toggles the grid separately. The H Alignment tool aligns objects even with the grid hidden ([bottom bar](https://dungeondraft-encyclopaedia.gitbook.io/guide/introduction/new-map-first-steps/useful-interface-buttons.md)). Vanilla snapping is to the full or half grid cell, and a Preferences option picks which ([main menu](https://dungeondraft-encyclopaedia.gitbook.io/guide/introduction/first-look/main-menu.md)). The gitbook documents **no Alt/Ctrl/Shift temporary snap override while dragging**. Ctrl-merge for walls needs snap on ([shortcuts](https://dungeondraft-encyclopaedia.gitbook.io/guide/general-info/mouse-and-keyboard-shortcuts.md)). With snap off, a freestanding portal can sit mid-cell ([video 12:17](https://www.youtube.com/watch?v=LKbwhrC4vRA)). Lights do not snap in the Light tool but do in the Select tool. A freshly pasted asset may snap with an offset until it is deselected and reselected ([interactive areas](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/interactive-areas.md)). The Custom Snap mod adds quarter and eighth cells, hex and isometric grids, a custom offset and a "Snap Selection" button ([mods](https://dungeondraft-encyclopaedia.gitbook.io/guide/custom-assets-and-mods/some-useful-mods.md)). The gitbook is internally inconsistent about when Custom Snap was bundled, and an earlier search snippet said 1.1.1.0 while the gitbook says it ships with 1.2.0.0. We treat it as bundled in current builds.

## Design tab: Building, Wall, Portal, Roof, Cave and Pattern

### Building tool

The Building tool is the fast path: a shape plus a wall style plus a floor style in one gesture. Shapes are Rectangle, Circle or Freeform. In Freeform, click points, hold Shift to bend, and Delete/Backspace erases the last point. Choosing the "X" in the wall selector draws only the floor. A colour box under each selector opens a picker and a small arrow resets it. **Alt+draw removes area** from the building ([Building](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/building-tool.md)). The video draws several differently shaped buildings, then subtracts sections with Alt. Dragging beyond the canvas edge puts the wall on the map boundary ([video 8:34-9:37](https://www.youtube.com/watch?v=LKbwhrC4vRA)). Edit Points drags a point (the whole building updates), adds on click along a wall, and removes on hover plus Delete. A "Bevel Corners" toggle sets soft or sharp wall angles. The limits are meaningful for design. A building holds one wall type, so wall and floor cannot be edited with the Wall or Pattern tools. The wall shadow can only be turned off from the Select tool. The floor has randomness that re-rolls whenever the building updates, and Building walls merge with Cave walls while Wall-tool walls do not. The author recommends Wall plus Pattern Shape for anything beyond a ten-minute job ([Building](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/building-tool.md)). Third-party reviews add that overlapping rectangles merge into one outline, a rectangle between two shapes becomes a hallway, rooms keep their own floor colour, and placing a door cuts the wall ([Design tools](https://encounterlibrary.com/dungeondraft-basics/design-tools/), [groupfinder](https://groupfinder.eu/library/dungeondraft)). The gitbook does not mention merging, hallways or Building Wear on this page. Building Wear (None, Dust, Grime, Noise, Scratch) is in Map Settings and applies to Building and Cave floors only ([Map Settings](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/settings-tab/map-settings.md)).

### Wall tool

Choose a wall type, click to place points, and finish by Right-click, double-click or Enter. The gitbook's "Over/Under" tab sets whether the next wall sits above or below existing ones, and **this cannot be changed after drawing** without the Minor Utils mod, which adds Bring To Front and Send To Back ([Wall](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/wall-tool.md), [Minor Utils](https://dungeondraft-encyclopaedia.gitbook.io/guide/custom-assets-and-mods/some-useful-mods/minor-utils)). The colour box and its reset arrow work as in Building, and shadow and Bevel Corners are toggles. **Merge** is done two ways: hold Ctrl while drawing until you meet a second wall's end, or select two walls with click and Shift+click in the Select tool and press Merge Walls. **Continue** a wall by hovering its end and holding Ctrl while drawing. All of this needs Snap to Grid and the same wall type, and it does not work for T or X intersections ([Wall](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/wall-tool.md), [contextual controls](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/contextual-controls.md)). Walls cannot be moved as objects, only their points edited (the Move Walls mod fills that gap). Walls block light by default. UVTT export treats them as line-of-sight and movement blockers. Since 1.1.1.1 every default wall also exists as a Path. Thickness is not a setting. The Scalable Walls mod exists for that, so thickness comes from the wall texture. Caps and joint styles are not documented in the gitbook. The modding API lists a Joint property (Sharp, Bevel, Round) and an end-cap texture ([WallTool API](https://megasploot.github.io/DungeondraftModdingAPI/reference/WallTool/)). A known bug from about 1.1.0.6 to 1.2.0.1: Edit Points after placing portals misbehaves, and the workaround is to save and reopen or remove the portals first.

### Portal tool

By default a portal must sit on a wall (**Anchored**). Rotate 180 flips it. Toggling to **Freestanding** lets it go anywhere, rotating in 5-degree steps with the mouse wheel or a left-panel slider, and it always sits under walls. A Block Light / Allow Light toggle decides whether lights are blocked, and it only matters for lights that have Shadows on. The first library entry (red X) is a blank portal that simulates a hole. Freestanding portals cannot be resized (the Objects tool can, as default portals have been objects since 1.1.1.1 and larger portals arrived in 1.2.0.0) ([Portal](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/portal-tool.md)). In the 2020 alpha you chose Block Light before placing and could not change it afterwards. Today the Select tool changes Block Light and swaps the portal type ([contextual controls](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/contextual-controls.md)). Anchored portals and walls cannot be box-selected, only clicked ([interactive areas](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/interactive-areas.md)). The old manual says portals can be dragged along their wall. The API stores an anchored portal as wall id, the point index before it and a distance along the segment, so it survives point edits as a parametric position ([Portal API](https://megasploot.github.io/DungeondraftModdingAPI/reference/Portal/)). This is inconsistent with the documented rule that Edit Points removes portals, so treat survival as the better design we should adopt, not as vanilla behaviour. UVTT export loses the door/window distinction, which must be set in the VTT.

### Roof tool

Anything under a roof is hidden unless the roof sits on a different level. The gitbook calls roofs "a complex kind of Patterns". **Quickbox** is an axis-aligned rectangle drawn by dragging. **Manual** is a point-by-point angled roof with a **width slider** setting the roof size, and Shift bends it. Types are Gable, Hip and Dormer. Roof colour cannot be changed. Over/Under applies against other roofs and is fixed after drawing. Sun direction and shade contrast are **global** sliders affecting every roof, and shading can be turned off. Afterwards roofs can only be moved, rotated and resized in the Select tool, with no contextual controls. In Quickbox the drawn shape fixes orientation ([Roof](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/roof-tool.md)). Ridge direction rules and slider ranges are undocumented.

### Cave brush

Click-drag paints. Size comes from icons, wheel or `[` `]`. **Dig Cave** is the default mode and Alt erases. **Blast Open** is click-to-open entrances, Alt undoes, and "Show Blast Opened Areas" visualises them. Style and colour apply to every cave on the map, and the alpha slider makes the walls and ground transparent. Only the first of the two default styles is colourable. Caves interact with Building walls but not Wall-tool walls ([Cave](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/cave-brush.md)).

### Pattern Shape tool

Pick a pattern (top-left "X" is plain colour) and draw a Rectangle, Circle or Freeform shape, with the same Shift-bend and Delete behaviours as Building. A **layer dropdown must be set before drawing**. Before placement you set texture rotation, colour, opacity and Outline. All of these, plus rotate, resize and texture swap, can be changed later in the Select tool. The middle of a pattern cannot be erased. The workaround is Edit Points: open a channel from the edge and close it inside. The Make Pattern Hole mod does this with Alt while drawing ([Pattern](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/design-tab/pattern-shape-tool.md)). A box selection that starts inside a pattern's bounds needs Shift held.

## Terrain tab: Terrain, Water, Material and Path

### Terrain brush

Up to **8 texture slots** (4 by default). The selected slot glows yellow, and a nine-squares icon opens the full texture window. Painting is **cumulative** (longer stays and higher intensity add more), textures replace one another, and a Fill button covers the canvas. Smooth blending switches organic against smooth. Biome presets refill the first four slots and cannot be undone with Ctrl+Z. Terrain can be turned off for a transparent export, and there is no partial transparency ([Terrain](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/terrain-tab/terrain-brush.md)). The video's river workflow depends on two properties: terrains blend into each other under layered strokes, and swapping a slot's texture recolours every painted area at once, so one map becomes a snow, grass or sandstone variant in seconds ([video 3:31-8:03, 16:22-18:43](https://www.youtube.com/watch?v=LKbwhrC4vRA)). Terrain textures are seamless, around 2048 px, and their alpha channel is read as height for blending ([Custom Assets Guide](https://raw.githubusercontent.com/wiki/Megasploot/Dungeondraft/Custom-Assets-Guide.md)).

### Water brush

Paint with brush sizes or draw Rectangle, Circle or Freeform shapes, and Alt erases (the area turns blue while erasing). The video describes the same three shape modes: a straight canal, a round pond and a polygon, plus a free brush for the rough river edge ([video 4:22-5:26](https://www.youtube.com/watch?v=LKbwhrC4vRA)). Shallow colour sits near edges, deep colour far from them, and a blend-distance slider widens the transition. Colour changes apply only after the water shape is updated. "Disable Border" removes the black outline, and a transparent shallow colour with no border blends smoothly into terrain. A "Below Water" layer puts assets underwater, recoloured and slightly distorted. Known bug up to 1.2.0.1: large water bodies or water touching the map edge glitch. Water animation cannot be exported ([Water](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/terrain-tab/water-brush.md)).

### Material brush

Brush circles, wheel or `[` `]`, a layer dropdown, and a material texture. Releasing adds a border so the shape looks finite, and drawing again with the same material extends the shape. Alt erases only if the same material and layer are selected. The same material on different layers will not merge. "Move To Front" then clicking a material reorders materials on one layer, and ordering is otherwise unpredictable. A Smooth button rounds sharp corners ([Material](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/terrain-tab/material-brush.md)). Material tiles are `<name>_tile.png` plus `<name>_border.png`.

### Path tool

Left panel for settings, right panel for the library, with a Fuzzy-to-Exact search box (Enter searches). Click points, finish by Right-click, double-click or Enter, close by ending on the start, and remove the last point with Delete/Backspace. Settings: layer, **Width**, **Smoothness**, Over/Under, Block Light (it acts as a wall in UVTT export), and Transition In/Out (hard, fade, grow/shrink). Paths always sit under objects on the same layer. Drawing in the opposite direction flips top and bottom. A duplicated point makes a sharp corner. Paths are not colourable in vanilla. Width, smoothness and transitions are **fixed after placement**, while the style can be swapped in the Select tool ([Path](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/terrain-tab/path-tool.md)).

## Objects, Scatter, Select, Light, Environment, Text and Prefabs

### Objects tool

Left panel for settings, right for the library, click to place. **Mouse wheel rotates 15 degrees, Z+wheel 5 degrees, Right-click rotates 90 degrees, Alt+wheel scales, Shift+wheel cycles library objects, and holding A mirrors.** The old 0.9.2 manual had Alt+wheel cycle and Shift+wheel mirror, which the current page supersedes ([Objects](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/objects-tab/objects-tool), [shortcuts](https://dungeondraft-encyclopaedia.gitbook.io/guide/general-info/mouse-and-keyboard-shortcuts.md)). Settings are Layer plus Over/Under, a per-object Shadow toggle and Block Light. Colourable assets show a reddish tint and a picker, and a placed object keeps its colour until changed in the Select tool. The library offers tag filters, a Custom Set dropdown (the union of a set's tags), search with a Fuzzy/Exact slider and a "Used" tab of assets already on the map (not always accurate). Since 1.1.1.0 the bottom-right shows the asset's name and pack.

### Scatter tool

Select assets with Ctrl+click (add or remove) and Shift+click (range), then click or drag to place random picks. Shift+wheel cycles among the selected assets ([Scatter](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/objects-tab/scatter-tool)). The video does the same with the "crate" tag, Shift-click multi-select and random cycling ([video 13:35-14:24](https://www.youtube.com/watch?v=LKbwhrC4vRA)). Controls: random colours (click several palette swatches, and with none selected the asset turns bright red), a rotation slider with two independent ends (default -180 to +180, equal ends fix it), a scale slider (0.1 to 4, splitting into two ends once moved), and a Spread slider of -1 to +4 where lower is denser. Over/Under defaults to Over. Very large selections can freeze the app for several seconds. Minor Utils adds random mirror and presets, and Scatter Brush paints areas.

### Select tool (X)

X toggles Select and the previous tool. It works on Walls, Portals, Objects, Paths, Lights, Patterns and Roofs, but **not** on Water, Terrain, Caves, Materials, Building floors (the walls are selectable) or Text (which has its own sub-mode). Selection: click any non-transparent pixel (yellow hover box, blue when selected), drag a box, Shift+click or Shift+box to add. Transform zones: drag the blue central area to move, the yellow zone to rotate (wheel 30 degrees, Z+wheel 10 degrees), the green corners to resize, and zones keep constant screen size ([interactive areas](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/interactive-areas)). The left tab has a type Filter, a Layers filter, Copy and Paste (Ctrl+C/V), Delete, a vertical Mirror (not for Walls or Portals), **Lock/Unlock** (locked assets cannot mix with unlocked ones in a multi-select, and Alt+box selects only locked), Make Prefab/Separate and Previous Tool ([left tab](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/left-tab)). Contextual controls: Objects get layer, front/back, shadow, Block Light and colour. Walls get Merge, type, colour and shadow. Portals get Block Light and type. Paths get layer, front/back, Block Light and style. Lights get intensity, shadows, colour, style and a radius ring. Patterns get layer, front/back, texture rotation, texture swap, colour and opacity. Roofs get none ([contextual controls](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/select-tool/contextual-controls)). There is no align or distribute (the Essential Utils mod adds it) and no native grouping outside Prefabs.

### Light tool and Environment

Click to place a light. Range comes from a slider or the wheel, plus Intensity, Colour, Style (three default shapes), a Shadows toggle per light, and a global Widget (flame) icon. Walls and portals always block light, and paths and objects block only with Block Light on. Alt+wheel rotates a light. Placing a light a few pixels from an asset's border makes a cone. Range beyond the tool limit comes from dragging the dotted ring in the Select tool. L toggles the lighting preview ([Light](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/effects-tab/light-tool)). Environment is one **ambient light colour** (white is no change, light blue is night). The video uses darker for night, orange/red for sunrise or sunset, purple for dusk and white for midday, and stacks lights to brighten ([video 14:39-18:43](https://www.youtube.com/watch?v=LKbwhrC4vRA), [Environment](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/effects-tab/environment)).

### Text tool and Prefabs

Text has an Edit mode (click to create or edit, Delete, font dropdown, size by typing, arrows or wheel, colour, and a Text Box with square or rounded shape, border width and box colours) and a Move mode (drag). It is **one line only**, formatting applies to the whole text, and it has no shortcuts. Sharpen Fonts and Visible are global toggles ([Text](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/text-tool)). Prefabs group Objects, Paths, Patterns, Roofs and Lights: select, Make Prefab, name it and pick a Set. A placed prefab moves and scales as one, and Separate ungroups one instance. Prefabs are shared by copying folders in the user folder's `prefabs` directory ([Prefabs](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/prefabs-tool)).

## Layers, Over/Under and levels

**Layers.** Layer management applies only to Patterns, Materials, Paths and Objects. Everything else uses fixed tool layers shown greyed out. The default is "100: User Layer 1" and higher numbers draw above ([Layers & Sorting](https://dungeondraft-encyclopaedia.gitbook.io/guide/general-info/layers-and-sorting)). The full 0.9.2.0 list, from bottom to top, is:

| ID         | Layer              | Notes                 |
| ---------- | ------------------ | --------------------- |
| -500       | Terrain            | fixed                 |
| -400       | Below Ground       | default for materials |
| -300       | Caves              | fixed                 |
| -200       | Floor              | fixed                 |
| -100       | Below Water        | selectable            |
| 0          | Water              | fixed                 |
| 100 to 400 | User Layers 1 to 4 | object default is 100 |
| 500        | Walls              | fixed                 |
| 700        | Above Walls        | selectable            |

Source: [Manual 0.9.2](https://www.docdroid.net/file/download/mDwhitS/dungeondraft-v0920-toxic-pangolin-the-unofficial-manual-pdf.pdf). Trace Image draws between Water (0) and User Layer 1 (100) ([Trace Image](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/settings-tab/trace-image)). Version 1.2.0.0 added keys for Above Roofs, which proves a layer above roofs exists, but **its number and the numbers of Portals and Roofs are not published as text**. I infer (unconfirmed) that 600, 800 and 900 are portal, roof and above-roof slots. Layers are stored in the map file's "layers" section, and the Manage Layers mod adds, renames and reorders them (for example, ID -101 sits before Below Water at -100).

**Over/Under.** "Over" puts the next placed item above existing items of the same layer, as if on a higher layer. "Under" puts it below. A table on layer 2, chairs on layer 1 and a lantern on layer 3 gives the same result as everything on layer 1 with Under for the chairs and Over for the lantern ([Manual 0.9.2](https://www.docdroid.net/file/download/mDwhitS/dungeondraft-v0920-toxic-pangolin-the-unofficial-manual-pdf.pdf)). After placement, the Select tool changes an item's layer and brings it to the front or sends it to the back. Wall, Roof and Path sorting is chosen when drawing, and cannot be changed afterwards in vanilla.

**Levels.** A level is a full independent map with its own terrain on/off, lights and settings, and a new level starts with Terrain off (transparent). Create via the Level Settings button or a right-click list: label, an optional level to clone, and an option to switch to it. Reorder by drag (visual only), rename by clicking, delete irreversibly (one must remain). Page Up and Page Down switch level, and the bottom bar shows a dropdown and arrows. **Compare Levels (C)** shows a reference level beneath the current one, with opacity sliders and number boxes. The author recommends reference at 100% and current at about 50% ([Level Settings](https://dungeondraft-encyclopaedia.gitbook.io/guide/all-the-tools/settings-tab/level-settings)). The video sets both at roughly 60% to line up stairs and walls, and uses the cursor's grid coordinate readout to match levels ([video 18:59-20:54](https://www.youtube.com/watch?v=LKbwhrC4vRA)).

## Custom asset packs: what a clone must read

The pack format is `.dungeondraft_pack` (zip, rar and loose images do not work), loaded from a folder via the Assets dialog and applied after a full restart. The folder must avoid the install directory, cloud folders and special characters, and Forgotten Adventures-size packs can take 10 to 30 minutes to load ([assets menu](https://dungeondraft-encyclopaedia.gitbook.io/guide/introduction/first-look/assets-menu.md)). Everything is authored at **256 px = one grid square** ([Custom Assets Guide](https://raw.githubusercontent.com/wiki/Megasploot/Dungeondraft/Custom-Assets-Guide.md)). The category folders under `textures/` decide use, and JSON files under `data/` carry metadata:

| Kind               | Folder and file                                                              | Requirement                                                                       |
| ------------------ | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Objects            | `textures/objects/` (subfolders allowed)                                     | PNG; tags in `data/default.dungeondraft_tags` (Tags and Sets sections)            |
| Colourable objects | tagged "Colorable" (capital C)                                               | Recolour area drawn in a "generally reddish" tone; no numeric threshold published |
| Terrain            | `textures/terrain/`                                                          | seamless, ideally 2048 x 2048; alpha = height                                     |
| Materials          | `textures/materials/`                                                        | `<name>_tile.png` and `<name>_border.png`, 1 px transparent gap                   |
| Tilesets           | tilesets folder + `data/tilesets/*.dungeondraft_tileset`                     | Simple 1024x1024 (4x4=16), Smart 1024x2048 (32), Smart Double 2048x2048 (64)      |
| Patterns           | `textures/patterns/normal/` or `colorable/`                                  | seamless; colourable use fully red areas                                          |
| Walls              | long seamless PNG + `<name>_end.png` + `data/walls/<name>.dungeondraft_wall` | black-and-white texture; line-of-sight cut auto-generated in the middle           |
| Paths              | `textures/paths/`                                                            | long, tiling left-right, 1 px transparent gap                                     |
| Portals            | `textures/portals/`                                                          | exactly 256 px wide, centred, no data file                                        |
| Lights             | `textures/lights/`                                                           | square grayscale, white lets light through                                        |
| Roofs and Caves    | `textures/roofs`, `textures/caves`                                           | **no authoring rules published**                                                  |

Packaging needs a `pack.json` (name, id, version, author) and an optional 256 x 320 `preview.png`. Deleting `pack.json` before repackaging makes the pack a new one after assets are removed or renamed ([Custom Assets Guide](https://raw.githubusercontent.com/wiki/Megasploot/Dungeondraft/Custom-Assets-Guide.md), [Go Packager](https://raw.githubusercontent.com/Ryex/Dungeondraft-GoPackager/master/README.md)). Packs with the same ID hide each other, and same-named tags and tag sets from several packs merge ([FAQ](https://dungeondraft-encyclopaedia.gitbook.io/guide/further-info/common-issues-and-questions.md)). No load-order rule is published. Dragging an image onto a map is a fallback that bloats the file and crashes more often ([drag and drop](https://dungeondraft-encyclopaedia.gitbook.io/guide/custom-assets-and-mods/importing-assets/drag-and-drop.md)).

## Export, map settings, mods and versions

**Export.** PNG is lossless with transparency, JPEG has no transparency, WEBP is smaller with transparency, and Universal VTT (.dd2vtt) embeds a PNG plus walls, portals, caves and lights. The recommended quality is 75 to 90%, and for a 5000x5000 px map JPEG at 90% is about 4.4 MB (WEBP 2.8 MB). Resolution is Grid PPI (default 256, **capped at 300**); typing a value and pressing Enter updates the displayed size, and a presets dropdown includes Roll20 (270 px per square, per the video). Most VTTs reject images over 16384 px, so a 200-square map needs about 81 PPI (our arithmetic). Crop and Reset Crop exist. Visual options: Grid and Lighting toggles, Camera Filter (None, Printer-Friendly, Sepia), Source Level, and an Overlay Level with Opacity, Focus and Brightness, where below 100% Focus or Brightness disables lights ([quality](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/quality-settings.md), [visual](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/visual-settings.md), [UVTT](https://dungeondraft-encyclopaedia.gitbook.io/guide/final-steps/exporting-your-map/universal-vtt.md)). The video exports the ground level with an overlay of the first floor, and also exports gridded and ungridded copies of the same map ([video 21:01-23:30](https://www.youtube.com/watch?v=LKbwhrC4vRA)). The trace image is not exported without a mod. A new-map dialog sets size up to **200 x 200** (the 0.9.2 manual said 128) and offers templates (the video shows TV and paper presets), three feature-disable checkboxes and a Map Wizard (Dungeon or Cave, with Boundary, Complexity and Density, producing only a starting layout) ([new map](https://dungeondraft-encyclopaedia.gitbook.io/guide/introduction/new-map-first-steps.md)). **Map Settings** hold Grid Style (default dotted), colour and opacity, Camera Filter and Building Wear. Trace Image works at 256 ppi, so scale = 256 divided by the image's ppi.

**Mods.** Mods are folders with a `.ddmod` JSON and Godot `.gd` scripts, enabled only from the start screen's Mods button. They add behaviour such as Custom Snap, Minor Utils, Manage Layers, Essential Utils, Move Walls, Make Pattern Hole, Colour and Modify Things and a UVTT WebP exporter ([mods menu](https://dungeondraft-encyclopaedia.gitbook.io/guide/introduction/first-look/mods-menu.md), [Modding API](https://megasploot.github.io/DungeondraftModdingAPI/)). The gitbook has no "mod export" feature, only export-format scripts in the API.

**Versions.** The gitbook is current to 1.2.0.1. Dated facts: 0.9.2.0 (2020 manual); the video was recorded in the March 2020 alpha; 1.1.1.0 added the hotbar, UI tint and asset name display; 1.1.1.1 added languages, portals as objects and walls as paths; 1.2.0.0 added layer hotkeys and larger portals; 1.2.0.1 fixed the Custom Snap and export-slider bugs (the release date of September 2025 and the 1.1.x dates come from secondary search snippets and are unverified). Differences between 2020 and now matter for the clone: Block Light is now editable after placement, and the Objects wheel/Shift/Alt bindings changed.

## The two videos and their step-by-step workflows

**LKbwhrC4vRA ("Dungeondraft Basics Tutorial", Anto, Icarus Games, 25 min, 13 March 2020)** is the only video with an obtained transcript, and it is auto-generated audio with mis-hearings and an alpha-version UI. Its workflow is natural features first, buildings second ([video](https://www.youtube.com/watch?v=LKbwhrC4vRA)). ## Remaining gaps

The evidence is strong on tool controls and weak on internals. The following items remain unresolved and should be checked in the app itself or in a real `.dungeondraft_map` file before they drive code.

- **Video 7yD0hHzKJAE** (Moulk's Map Lab, 2024): no transcript, chapters, or description was obtainable, so its workflow, hotkeys and asset advice are unknown. Fetch it with YouTube "Show transcript" or yt-dlp.
- **The gitbook "unofficial-dd-manual" (https://unofficial-dd-manual.gitbook.io/)** was not read. The old 0.9.2 PDF was read instead. It is out of date on layers, scatter mechanics and keys.
- **Current layer numbers**: 600, 800 and 900 and the Above Roofs ID are unconfirmed; the gitbook shows the list only as a screenshot. Open the Manage Layers mod or a v1.2 map file.
- **Documented but unread or undocumented behaviours**: Enter, Esc, Right-click and double-click for Building, Pattern Shape, Roof and Cave; wall thickness, caps, joint geometry; roof ridge and slider ranges; the red-colourable threshold; stairs and pillars (presumably plain objects); the Minor Utils and Preferences shortcut lists (screenshots); a per-level versus per-map setting table; whether any grid-free map exists.
- **Pack internals**: `pack.json` and `.dungeondraft_tags` schemas, roof and cave pack requirements, container format, and load order. None is published in the sources reached.
- **Version history**: no primary changelog for 1.0.x to 1.2.x. The 1.1.1.0 (about October 2024), 1.1.1.1 (about March 2025) and 1.2.0.1 (September 2025) dates come from secondary snippets. The gitbook pages disagree on whether the export brightness-light bug is fixed in 1.2.0.1.
- **The video's ASR text** garbles several words (for example "debt tool" for a terrain slot). The alpha UI differs from today's.
- **Native map format and terrain encoding**: unknown, which matters only if we ever import `.dungeondraft_map` files.

## Conclusion

The central finding is that Dungeondraft already is the type-less editor the owner wants, and what makes it feel coherent is not any one tool but a single pointer grammar plus a short, fixed layer stack with an Over/Under flag. Reproducing that grammar once, in a shared PixiJS state machine with Edit Points, Alt-erase and the finish/cancel keys, is worth more than copying tools one at a time, and it is also where touch needs explicit extra buttons that Dungeondraft never had.

The second finding is how many vanilla limits are cheap to beat: sorting and path settings locked after placement, no pattern holes, no wall thickness, no align/distribute, one-line text and no scale unit. Fixing these in our own tools gives a clear edge. The first things to settle before coding are the terrain representation (chunked raster against vector soft edges) and the layer-ID table, since most other tools hang off those two decisions.
